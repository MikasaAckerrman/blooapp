# blooapp

Менеджер веб-приложений для Android: любой сайт превращается в отдельное
полноэкранное окно с собственной иконкой на домашнем экране, своими
настройками и — при поддержке устройства — изолированной сессией, чтобы
держать два аккаунта одного сайта одновременно.

Это не браузер. Браузер показывает много сайтов в одном окне; blooapp даёт
каждому сайту своё окно, свою задачу в «Недавних» и свой набор настроек.

## Состояние

Фундамент. Собраны и покрыты тестами модули, которые не зависят от Android:

| Модуль | Что делает | Тесты |
|---|---|---|
| `:core-model` | нормализация и валидация адресов | 21 |
| `:core-diag` | диагностика нарушенных контрактов WebView | 28 |

Модуль `:app` — следующий этап; он единственный требует Android SDK и
собирается в CI.

## Зачем `:core-diag`

Приложение-обёртка над WebView почти никогда не падает в месте дефекта.
Типичные поломки не выражаются исключением вообще:

- не вызвали `filePathCallback` → поле `<input type=file>` залипает навсегда,
  ни лога, ни падения;
- вызвали `loadUrl(url)` и вернули `true` из `shouldOverrideUrlLoading` →
  навигация зацикливается (в одном известном проекте это давало 200+ вкладок
  на один тап);
- вернули `false` из `onRenderProcessGone` → систему убивает приложение, и в
  отчёте будет «краш» вместо причины.

`ContractMonitor` — машина состояний, которая знает эти контракты и сообщает
о нарушении сразу. `DiagSink` доставляет события, не роняя приложение и не
блокируя поток. Коллектор (`tools/collector`) агрегирует их и выдаёт вердикт
«что сломано», помечая часть кодов как блокирующие релиз.

Каждый код диагностики обязан ссылаться либо на номер issue в чужом трекере,
где дефект подтверждён у реальных пользователей, либо на пункт чек-листа —
это проверяется тестом, чтобы в мониторе не появлялись догадки.

## Сборка и проверка

```sh
./gradlew :core-model:test :core-diag:test   # тесты, работают без Android SDK
sh tools/verify.sh                           # то же + сводка
sh tools/diag.sh start                       # коллектор на 127.0.0.1:8799
sh tools/diag.sh report                      # что сломано прямо сейчас
```

Требования: JDK 17. Gradle подтягивается wrapper'ом.

## Целевая платформа

`minSdk 26` (покрытие ~96 % устройств), `targetSdk 36` — обязателен для
публикации в Google Play с 31 августа 2026.
